Задание 1
Опишите основные преимущества использования масштабирования методами:

активный master-сервер и пассивный репликационный slave-сервер;
master-сервер и несколько slave-серверов;
Дайте ответ в свободной форме.

Активный master-сервер и пассивный slave-сервер

В данном случае все основные запросы идут на master-сервер. На нем происходит чтение, запись и изменение данных. Slave-сервер при этом получает изменения с master и хранит у себя копию данных.

Основное преимущество такой схемы — отказоустойчивость. Если с master что-то произойдет, можно переключиться на slave и использовать его вместо вышедшего из строя сервера.

Также slave можно использовать, например, для создания резервных копий, чтобы дополнительно не нагружать master.

Приложение
     |
     v
+----------+
|  Master  |
|  R / W   |
+----------+
     |
     | репликация
     v
+----------+
|  Slave   |
| passive  |
+----------+
Master-сервер и несколько slave-серверов

Здесь схема работает примерно так же, но появляется несколько slave-серверов.

Все операции, которые изменяют данные (INSERT, UPDATE, DELETE), выполняются на master. Запросы на чтение (SELECT) при этом можно распределить между несколькими slave.

                    Master
                 запись данных
                       |
            +----------+----------+
            |          |          |
            v          v          v
         Slave 1    Slave 2    Slave 3
          чтение     чтение     чтение

То есть если у нас становится много запросов на чтение, они не будут все идти на один master. Часть запросов можно отправлять на разные slave-серверы и тем самым уменьшить нагрузку на master.

Получается, что основные преимущества такой схемы:

можно распределить нагрузку на чтение между несколькими серверами;
снижается нагрузка на master;
при росте нагрузки можно добавлять дополнительные slave;
один из slave можно отдельно использовать для отчетов или резервного копирования;
повышается отказоустойчивость, так как существуют дополнительные копии данных.

Задание 2
Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц:

пользователи,
книги,
магазины (столбцы произвольно).
Опишите принципы построения системы и их разграничение или разбивку между базами данных.

Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.

Допустим, у нас есть база данных из трех таблиц:

users:

id;
name;
email;
city.

books:

id;
title;
author;
price.

shops:

id;
name;
city;
address.

Для этой базы можно одновременно использовать вертикальное и горизонтальное шардирование.

Вертикальное шардирование

Сначала можно разделить данные по их назначению. То есть пользователей хранить в одной базе, книги в другой, а магазины в третьей.

                         Приложение
                             |
          +------------------+------------------+
          |                  |                  |
          v                  v                  v
      DB_Users           DB_Books           DB_Shops
        users              books              shops

Получается, что каждая база отвечает за свою часть данных и при необходимости может находиться на отдельном сервере.

Плюс такого варианта в том, что каждую часть можно масштабировать отдельно. Например, если основная нагрузка идет на каталог книг, можно увеличить ресурсы серверов с DB_Books, при этом остальные части базы не трогать.

Горизонтальное шардирование

Если таблицы становятся слишком большими, их уже можно дополнительно разбить по строкам.

Например, пользователей можно распределить по их id:

users:

id 1–100000       -> Shard 1
id 100001–200000  -> Shard 2
id > 200000       -> Shard 3

Таблицу с книгами можно разделить таким же образом:

books:

id 1–500000       -> Shard 1
id > 500000       -> Shard 2

Магазины, например, можно распределить не по id, а по регионам:

shops:

Москва             -> Shard 1
Санкт-Петербург    -> Shard 2
Остальные регионы  -> Shard 3

В итоге общая схема будет выглядеть примерно так:

                           Приложение
                               |
                         Shard Router
                               |
          +--------------------+--------------------+
          |                    |                    |
          v                    v                    v
        USERS                BOOKS                SHOPS
          |                    |                    |
     +----+----+          +----+----+          +----+----+
     |         |          |         |          |         |
     v         v          v         v          v         v
  Shard 1   Shard 2    Shard 1   Shard 2    Shard 1   Shard 2

То есть сначала мы разделили базу вертикально: отдельно пользователи, книги и магазины. После этого каждую большую таблицу можем дополнительно разделить горизонтально между несколькими серверами.

При этом для каждого шарда можно использовать master и slave:

             Master
             R / W
               |
               | репликация
               v
             Slave
              Read

На master будут выполняться операции записи и изменения данных. Slave будет получать копию данных с master и может использоваться для чтения или в качестве резервного сервера.

В итоге шардирование позволяет нам распределить сами данные и нагрузку между разными серверами, а репликация позволяет иметь дополнительные копии этих данных и повысить отказоустойчивость системы.
